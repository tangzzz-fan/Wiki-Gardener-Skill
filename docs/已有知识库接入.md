# 已有知识库接入指南

你**已经有一堆 Markdown / Obsidian 笔记**，只是以前没按园丁规矩整理——现在想用本 skill 管**以后**的生长，并逐步收拾旧内容。可以，而且这是最常见的真实场景之一。

空文件夹冷启动见 [README](../README.md)。按个人经验改域档案见 [自定义与调教指南](./自定义与调教指南.md)。

---

## 1. 核心原则

1. **先立规矩，再搬家具**：先完成宪章 + `00_系统/` 骨架，再批量收拾旧文。  
2. **旧内容不必一次完美**：第一轮目标是「能路由、能去重、能挂分区」；事实精修可以后做。  
3. **唯一入口仍是 `10_inbox/`**：要让园丁处理的旧文，最终都要进 inbox 走吸附（或明确「就地登记」例外，见下）。  
4. **你的原文优先备份**：大搬家前复制整个库或 `git commit`，再动目录。

---

## 2. 推荐总流程（五步）

```
装 skill → 指定「就是这个已有文件夹」为 vault
  → 说「帮我初始化一个知识库」（承认非空、走已有库路径）
  → 确认宪章 / 画像 / Atlas 分区
  → 把待整理旧文放入 10_inbox/（或按策略分批）
  → 「整理一下 inbox」批量吸附
  → 以后新内容只进 inbox；旧债用园艺慢慢还
```

对 Agent 可直接说：

> 这是我已经在用的笔记库，比较乱。请按「已有知识库接入」帮我初始化，不要当成空库把我的文件删掉；旧文我想分批进 inbox 整理。

## 3. 已有内容怎么处理（三种策略）

按旧库体量与混乱程度选，可组合。

### 策略 A：全量漏斗（乱成一锅时最干净）

适合：目录无章法、大量重复、你也分不清哪些是正本。

1. **备份**整库。  
2. 初始化在本目录（或空目录）建好 `00_系统/`、`10_inbox/`、`20_领域/<分区>/`、`90_archive/`。  
3. 把**待纳入**的旧 `.md`（可先排除纯日记/附件说明）**移动或复制**到 `10_inbox/`。  
4. 说「整理一下 inbox」→ 走 [批量吸附](../skills/wiki-gardener/references/setup-wizard.md)（合并/拒收汇总批卡片）。  
5. 结果进 `20_领域/<分区>/`，垃圾进 `90_archive/`，inbox 清空。

注意：一次丢几百篇会审不过来——**按主题分批**（先 iOS、再生活）更可控。

### 策略 B：分批漏斗（推荐大多数人）

适合：旧库能用，但想逐步变好，又不想停更。

1. 初始化：在现有根目录**补上** `00_系统/` 等（见下「就地脚手架」）。  
2. **本周只搬一类**进 `10_inbox/`（例如所有带「BLE」的笔记）。  
3. 吸附干净后，日常新笔记走 inbox；下周再搬下一批。  
4. 未搬动的旧路径暂时保留——当作「历史堆」，**不要**假装它们已经过吸附；需要引用时再搬进 inbox。

### 策略 C：就地登记 + 轻量挂载（已有较清晰文件夹时）

适合：你已有「工作/学习」等目录，结构勉强可用，只缺宪章与园丁流程。

1. 初始化时创建 `00_系统/`、`10_inbox/`、`90_archive/`；`20_领域/` 可与现有主内容目录对齐或逐步迁入。  
2. **不要**未经吸附把整棵旧树声明成「已合规正本」。  
3. 对「已经很好、确定要留」的少量篇目：可请园丁做**登记式吸附**——读内容、写 frontmatter、挂 MOC、链相关篇，文件可从原路径迁入对应 `20_领域/<分区>/`（仍须人话确认，L3）。  
4. 其余仍用策略 B 分批进 inbox。

红线：禁止 Agent 静默全盘重命名/删除；禁止跳过宪章直接「帮你整理完」。

## 4. 「就地脚手架」时目录长什么样

在已有笔记根目录执行初始化后，目标形态：

```text
你的旧库根/
├── 00_系统/          # 新建：宪章、atlas、domains、决策日志
├── 10_inbox/         # 新建：唯一整理入口
├── 20_领域/          # 新建或逐步迁入；一层 Atlas 分区夹
├── 90_archive/       # 新建
├── （旧文件夹…）     # 暂留；内容分批进 inbox，或登记后迁走
└── …
```

- 若旧库已是 Obsidian 库：保留 `.obsidian/`，只加上述约定目录即可。  
- 旧文文件名可以暂时很丑；吸附时可改成「标题即结论」的原子名（须你同意）。

## 5. 批量吸附时，旧文会被怎样对待

与空库倒入历史文档同一套规则（详见 `intake.md`）：

| 情况 | 动作 |
|---|---|
| 多篇几乎同一结论 | 建议 **merge**，留一篇正本 |
| 同主题族、结论不同（相关补缺） | **新建**并互链，不硬揉 |
| 明显违宪章 / 无价值碎片 | **拒收** → `90_archive/`（不删） |
| 有事实硬伤 | 标出来；重要篇可先 domain-expert 再挂（可分批，首轮不必篇篇精审） |
| 归不进已有分区 | 暂放 `20_领域/_未归类/`，稍后扩分区 |

首轮批量以**结构**为主：去重、分区、MOC、日志。  
「这篇 API 写错了」类精修，放在你开始**日常使用**之后，对高价值篇做审查即可。

---

## 6. 初始化之后怎么用（旧债 + 新流）

| 节奏 | 做什么 |
|---|---|
| 每天 | 新想法 / 剪藏 → 只丢 `10_inbox/` → 「整理一下 inbox」 |
| 每周 | 从旧堆再搬一批进 inbox（策略 B） |
| 双周 | 「给知识库做个体检」去重、找孤儿 |
| 随时 | 「以 xx 专家审这篇」加厚域档案（见自定义指南） |

成功标准（不必一次达到）：

- [ ] 有宪章，且你认可北极星  
- [ ] 新内容只进 inbox，不再随手塞随意文件夹  
- [ ] 旧堆在缩小，决策日志在变厚  
- [ ] 你知道重复会被问、拒收进 archive 不丢文件

## 7. 对 Agent 的触发语（可复制）

**接入已有库：**

> 当前文件夹是我已有的笔记库（非空）。请按 wiki-gardener「已有知识库接入」初始化：保留我的旧文件，先建 `00_系统` / `10_inbox` / `20_领域` / `90_archive` 与宪章访谈；旧文我稍后分批放进 inbox。

**分批收拾：**

> 我把一批旧笔记放进 `10_inbox/` 了，请批量吸附：合并/拒收汇总成卡片给我一次确认；相关补缺要新建互链，不要因为主题相近就硬合并。

**体检：**

> 给知识库做个体检，重点看重复和 `_未归类`。
