# 为什么 human-writing 写得好（本库学习笔记）

对照评测：`tests/eval-runs/prose-ab-2026-08-07/RESULTS.md`（同一批 `domain-expert` 初稿上，本 skill 外化改稿在自然度 / 去 AI 痕迹上稳定优于基线与 humanizer）。

本文拆的是**可复用的设计点**，方便以后 fork 调教；不是吹捧上游作者。

## 1. 材料门槛先于文笔

多数「去 AI 味」skill 只洗句式。本包先问：**手里有没有够撑篇幅的具体材料**（非虚构长文内部至少五件可追溯材料，且能串成过程）。

- 材料不够 → 研究 / 追问 / 缩短，禁止用「比如有个人」脑补。
- 这直接压住「越写越空」——空稿的 AI 味往往来自同义反复，不是缺几个禁词。

本库接线时：外化改稿只许用库内笔记与用户已给材料，**不得**为活人感捏造踩坑经历。

## 2. 说话位置 > 口头禅

「活人感」被定义为：谁在说、凭什么知道、在意哪一点、判断依据到哪里为止——而不是加「老实说」「兄弟们」。

改稿第一遍优先处理「换模型也能原样写」的匿名段：补来路与取舍，而不是堆语气词。

## 3. 段落必须推进

硬规则：新段落要带来新事实、新动作、新例子、新区别或新后果；同义换说法不算。

配合压缩试验（删掉约三分之一若信息不变 → 原稿在注水）。知识库外化时，这比堆「其次 / 更深一层」更有用。

## 4. 中文硬禁令可机器扫

正文禁冒号路标、破折号、翻案腔（「不是……而是……」族）、一批商业黑话与模型路标；`scripts/check_prose.py` 把契约落成可跑检查。

好处：Agent 与人有同一张「交稿不及格」清单。调教时先改清单与 `references/revision.md`，再改散文审美。

## 5. 按需加载 references，不一次灌满

`forum-prose` / `reality` / `fiction` / `formats` / `revision` 分流；`revision` 明确留到初稿之后。上下文干净，规则不易互相淹没。

## 6. 和本库其它写手的边界

| 写手 | 擅长 | 不该让它做 |
|---|---|---|
| `domain-expert` | 对 Vault 追问、域档案、吸附原生笔记、事实审查 | 对外公众号韵律 |
| `human-writing` | 中文外化读感、材料诚实、去模型腔 | 改领域对错、写进 `20_领域/` |
| `review-reviser` | 按审查 finding 修订 | 风格外化 |
| `humanizer`（未入库） | 英文百科式 AI 词痕 scrub | 当中文外化主路径（评测增益小于本包） |

理想顺序：

```text
domain-expert 成文（±审查/reviser）→ 吸附可选
  → human-writing 外化（人味）→ 90_export/
  → frontend-slides / 配图 / 封面（读外化稿）→ 90_export/
```

视觉呈现 skill 对中文外发是**软建议**先外化，不是强制门禁。

## 7. 以后若要改，先动哪里

1. 禁令过严/过松 → `SKILL.md` 成稿禁令 + `scripts/check_prose.py` + `references/revision.md`
2. 外化仍像报告 → `references/forum-prose.md` 节奏段
3. 事实漂移 → 加固本仓库接线表「信息保真」；评测用 prose-ab 复跑
4. 不要把本包规则写死进 `domain-expert` 铁律——库内笔记与外发文案目标不同
