# 知识地图规则

## 证据模型

节点必须来自可定位的 Markdown 标题或该标题下明确命名的概念。每个节点保留：

- 稳定节点 ID
- 简短显示名
- `[[来源笔记#标题]]`
- 可选的 `concept_id`
- 个人掌握图中的状态

边必须能由以下至少一种证据支持：

- Atlas/MOC 的显式层级或导航
- 来源正文中的因果、依赖、对比、顺序或例证表述
- 笔记之间的显式双链及其上下文

仅有共同关键词不足以建立关系。证据不够时放入“未纳入项”，说明缺什么。

## 两类地图

### 知识结构图

用于回答“这些知识如何组织”。状态不参与节点选择。优先保留主干、关键关系和边界，避免把目录树原样复制成大图。

### 个人掌握图

用于回答“我对这套结构掌握到哪里”。先建立知识结构，再从掌握索引叠加状态：

- 找到匹配 `concept_id` 时使用索引状态。
- 只能按来源标题对齐但无法唯一对应概念时，标注“状态未对齐”。
- 索引没有记录时使用 `unseen`。
- 发现来源 fingerprint 变化时标注“待状态刷新”，保持索引只读。

地图是状态视图，不产生答题证据，也不改变 `learning`、`mastered` 或 `review_due`。

## Mermaid 约束

- 默认使用 `flowchart LR`；层级明显且较深时可用 `flowchart TD`。
- 节点 ID 使用 ASCII 字母开头，只含字母、数字和下划线。
- 显示文本放在双引号节点中，并转义双引号。
- 边标签使用“包含”“依赖”“导致”“对比”“例证”“下一步”等可验证动词。
- 图超过约 30 个节点时按 MOC 分区拆成多张图，另给总览图。
- 不依赖颜色传递唯一信息；掌握状态同时写入节点索引。
- Mermaid 代码块内不放 wikilink，以免渲染器差异破坏图；wikilink 放在紧随其后的节点索引。

## 可追溯输出

节点索引使用列表，避免宽表在窄屏难读：

```text
- N1 概念名
  - 状态：learning
  - 来源：[[20_领域/示例.md#概念名]]
```

关系依据逐边记录：

```text
- N1 -> N2（依赖）
  - 依据：[[20_领域/示例.md#关系说明]]
```

这里的路径仅是格式示例，不表示绑定某个领域或真实文件。

## 降级策略

- Mermaid 不支持所需布局时，保留 flowchart 和分区，不切换到不可移植语法。
- 来源冲突时，画出已确认的共同结构，把冲突关系移到未纳入项。
- 图过密时先删除低价值边，再拆分子图；不得通过隐藏来源解决拥挤。
- 掌握索引缺失时仍可生成结构图；若用户要掌握图，明确所有节点暂为 `unseen`，不创建或修改学习状态。
