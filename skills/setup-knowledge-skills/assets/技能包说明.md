## 技能分工

| Skill | 职责 |
|---|---|
| wiki-gardener | 初始化、吸附、园艺（该不该收、放哪、重不重） |
| domain-expert | 单篇执笔 / 审查（对不对） |
| setup-knowledge-skills | 仅安装后引导；日常可忽略 |

### Companion（只写本机已装；未装标「未装」，勿唤起）

| Skill | 类 | 职责 | 本机 |
|---|---|---|---|
| grill-me | 思考 | 成文前追问，收成共识提纲 | {{STATUS_grill-me}} |
| topic-resonate | 思考 | 选题/文稿是否真击中受众 | {{STATUS_topic-resonate}} |
| content-diagnose | 思考 | 选题通过后怎么做成好内容（诊断不代写） | {{STATUS_content-diagnose}} |
| script-flow | 思考 | 口播/脚本逻辑延续 | {{STATUS_script-flow}} |
| content-decomposer | 思考 | 对标拆解；产物可进 `10_inbox/` | {{STATUS_content-decomposer}} |
| frontend-slides | 呈现 | HTML 演示导出 → `90_export/` | {{STATUS_frontend-slides}} |
| ian-xiaohei-illustrations | 呈现 | 正文配图 | {{STATUS_ian-xiaohei-illustrations}} |
| gbro-cover-design | 呈现 | 封面提示词 | {{STATUS_gbro-cover-design}} |

setup 填写 `本机` 列时：写成 `已装` 或 `未装`。Agent **不得**对「未装」行冒充可运行。

协作习惯：**先审对不对，再决定收不收。** 思考产物进 `10_inbox/`，不直写 `20_领域/`。呈现类导出到 **`90_export/`**（或你指定的路径），不进吸附主路径。短视频向仍：**存在性先于形态性**（运营审核 → 编导/脚本 → inbox）。

建议流水线：想清楚（grill / resonate / diagnose / decomposer）→ 成文入库（expert → gardener）→ 导出呈现（slides / 配图 / 封面）。

## 常用触发语

- 建库：「帮我初始化一个知识库」
- 整理：「整理一下 inbox」
- 体检：「给知识库做个体检」
- 审稿：「以 \<领域\> 专家身份审一下这篇」
- 想清：「帮我 grill 一下这个想法」/ 「这个选题能不能打中人」
- 内容诊断：「选题过了，帮我做内容诊断」
- 拆对标：「按我的标准拆解这条对标」
- 口播：「检查这段口播哪里会划走」
- 导出：「把这篇做成 HTML 演示 / 配图 / 封面」（输出到 `90_export/`）

## 选装 / 补装 companion（终端）

思考最小集：

```bash
npx skills@latest add tangzzz-fan/Wiki-Gardener-Skill -g -y \
  --skill grill-me --skill topic-resonate --skill content-diagnose \
  --skill script-flow --skill content-decomposer
```

呈现：

```bash
npx skills@latest add tangzzz-fan/Wiki-Gardener-Skill -g -y \
  --skill frontend-slides --skill ian-xiaohei-illustrations --skill gbro-cover-design
```

单包示例：`npx skills@latest add tangzzz-fan/Wiki-Gardener-Skill -g -y --skill grill-me`

## 更新技能包（终端）

```bash
npx skills@latest update -g -y
```

不要执行 `npx skills update <仓库名>`（会找不到）。手拷安装的用户需先改走 `npx skills add` 才进入更新轨道。
