# script-flow —— 逻辑延续检查

找出「观众会在哪一秒跟不上」的点：段落衔接、信息密度、口播流畅度。

**改编说明**：见同目录 `NOTICE`。

## 何时触发

- 「检查逻辑延续」「稿子顺不顺」「哪里会划走」
- 「口播卡不卡」「有没有啰嗦的地方」
- 用户已有逐字稿/口播稿，需要微观衔接诊断（非整篇选题诊断）

## 不可违背

1. 禁止 emoji；风险用 `[高风险]` / `[中风险]` / `[小建议]`；改稿新增用 `[新增]`，撤回用 `[还原]`  
2. **不改论点、案例、数据**——只管「怎么说」  
3. 诊断完**主动问**是否标记式改稿；**不问就改**禁止  
4. 不直写 `20_领域/`；用户确认的改稿可落 `10_inbox/`

## 与相邻能力

| 能力 | 管什么 |
|---|---|
| `topic-resonate` / `content-diagnose` | 选题真伪、宏观做法 |
| **本 skill** | 微观衔接与口播 |
| `domain-expert` | 事实对错、领域深度 |
| 运营域审核（示例） | 该不该发（存在性先于形态性） |

## 核心原则

观众划走常见三类原因：

1. **逻辑断裂**：从 A 跳到 C，缺 B  
2. **信息密度掉了**：重复或绕圈  
3. **口播卡壳**：过长、过书面、连续自问自答

## 检查流程

### 1. 分段

按话题切换分段：段号、主题（一句）、功能（开场 / 铺垫 / 论证 / 案例 / 转场 / 高潮 / 结尾）。

### 2. 三维扫描

**逻辑衔接**：上段末句 → 本段首句是否可跟；缺什么过渡。  
**信息密度**：是否重复；删掉本段是否丢失关键信息。  
**口播流畅度**：单句过长、书面套话、术语无即时解释。

缺拍摄形态时问一句（算在 3 问配额内）：「纯口播还是白板/演示？」（白板清单与「看这里」类提示词标准不同。）

### 3. 风险等级

| 等级 | 含义 |
|---|---|
| `[高风险]` | 大概率在此划走 |
| `[中风险]` | 可能走神 |
| `[小建议]` | 改了更好 |

## 输出格式

```text
逻辑延续检查报告

【段落结构】
段号 | 主题 | 功能 | 状态
…

【问题清单】
[高风险] 第 X 段 → 第 Y 段：…
原文引用：…
修复建议：…

【整体评估】
逻辑衔接：…
信息密度：…
口播流畅度：…
总结：…

【询问】
要按标记式改稿吗？保留原文，用删除线表示建议删改，用 [新增] 标出改写。
```

## 标记式改稿（用户确认后）

- 永不抹除用户原文；原地对照  
- 删除/替换：`~~原文~~` + `[新增] 新句`  
- 误判撤回：`[还原] …`  
- 文末「改动清单」表：位置 / 类型 / 说明  
- 保持用户语气，避免「AI 腔」

## 注意事项

1. 修复建议必须能直接念  
2. 顺的稿子可以说「没什么大问题」，勿硬找茬  
3. 优先标高风险  
4. 判断「跑题」前：删掉后观众能否脑补出具体含义？脑补不出则可能是必要论证

## 与知识库协作

| 下一步 | 交接 |
|---|---|
| 改稿确认后留档 | `10_inbox/`，`origin: chat`，`status: draft` |
| 事实审查 | `domain-expert` |
| 入库 | 审过后 → `wiki-gardener` |
| 导出演示 | `frontend-slides` → `90_export/` |
