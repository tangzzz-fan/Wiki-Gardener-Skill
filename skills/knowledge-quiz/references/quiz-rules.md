# 测验规则

## 候选生成

先读用户指定范围，再沿 Atlas/MOC 与明确双链补足上下文。候选知识单元应能定位到一个来源标题，优先覆盖：

- 定义及适用边界
- 因果与机制
- 对比、取舍和反例
- 步骤的顺序与前置条件
- 跨笔记关系

不要从无来源的常识补题。来源冲突时暂停该候选，交给 `domain-expert` 做事实审查。

## 选题顺序

默认优先级：

1. `review_due`
2. 最近答错或部分正确的 `learning`
3. 从未测过的 `unseen`
4. 其余 `learning`

默认排除 `mastered`。用户明确要求全面复习、抽查已掌握内容或来源已变化时可以纳入。

默认跨会话排除历史上相同的 `question_signature`。用户明确要求重做原题时才允许纳入；复习错题时优先改变认知动作或被测关系，而不是只换题面。

## 认知动作

- `recall`：回忆名称、定义、步骤或事实。
- `explain`：用自己的话解释机制、原因或边界。
- `application`：把概念用于新情境、案例或决策。
- `relation`：说明两个以上概念之间的因果、对比、依赖或层级。

只有 `application` 与 `relation` 能满足掌握门槛中的高阶证据要求。

## 判定

判定必须以已读来源为依据：

- `[正确]`：关键关系完整，没有改变原意的错误。
- `[部分正确]`：核心方向正确，但缺少必要条件、边界或关系。
- `[需复习]`：核心关系错误、答非所问，或无法形成可验证回答。

反馈先给判定，再给来源、解析和薄弱点。解析应指出答案为何成立，不只复述标准答案。薄弱点应描述具体缺口，例如“记住结论但漏掉适用条件”，不要写泛化评价。

## 逐题交互

一次只给一题并等待回答。用户回答后完成判定和回写，再出下一题。只有用户明确要求以下形式时才偏离：

- 一次生成整套自测题
- 仅导出题库，不现场作答
- 限时批量作答后统一判定

批量模式仍需逐题保存独立 `question_signature` 和答题证据，不得用整套总分直接推导单个概念状态。

## 会话结束

汇总：

- 本轮新进入 `mastered` 的概念
- 仍为 `learning` 或 `review_due` 的薄弱点
- 因来源问题交给 `domain-expert` 的项目
- 建议下次复习的概念与认知动作

不以题量、总分或主观流畅感替代状态契约。
