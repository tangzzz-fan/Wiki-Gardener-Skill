# wiki-gardener 使用说明与调优指南

> 配套文件：本目录上级为 skill 本体（或打包后的 `wiki-gardener.skill`，v1.1）
> 本文档面向 skill 的使用者（含小白用户的引导者），说明如何安装、触发、日常使用，以及后续如何根据实际运行情况调优。
> 与同仓库 `skills/domain-expert/docs/使用说明与调优指南.md` 互为姊妹篇
> 开源总览与评测：仓库根目录 `README.md`、`tests/EVAL.md`（https://github.com/tangzzz-fan/Wiki-Gardener-Skill）

---

## 一、它是什么

wiki-gardener 是一个"知识库园丁"skill：配合 Karpathy LLM wiki 风格的原子笔记库（纯 Markdown + MOC 索引 + 双向链接），负责三件事——**初始化建库、日常吸附新内容、定期园艺审计**。它是策展人不是作者：只判断"该不该收、放哪、是否重复"，正文修改走独立的编辑流程。

skill 内部结构（使用时报错排查用）：

```
skills/wiki-gardener/
├── SKILL.md                  # 主入口：角色定位 + 三大模式路由 + 权限铁律
├── references/
│   ├── setup-wizard.md       # 模式一：初始化访谈向导
│   ├── intake.md             # 模式二：吸附工作流 + 诊断单 Schema
│   ├── gardening.md          # 模式三：园艺审计 + 去重/偏离协议
│   └── autonomy.md           # 放权阶梯 + 健康指标 + 复盘闭环
├── scripts/
│   └── dup_scan.py           # 重复簇检测脚本（TF-IDF，中文免分词）
└── assets/templates/         # 宪章 / MOC / 原子笔记 / 决策日志 / 域档案模板
```

## 二、安装

**推荐**（短命令，装本仓库全部知识库 skill，并拉起 setup）：

```bash
./scripts/install_skills.sh
# 或：npx skills@latest add tangzzz-fan/Wiki-Gardener-Skill -g -y
```

装完后若未自动进入引导，对 Agent 说「运行 setup-knowledge-skills」。  
之后拉新版：`npx skills@latest update -g -y`。完整说明见仓库根目录 `README.md`。

园艺去重脚本可选：`pip install -r requirements.txt`（仅 `dup_scan.py` 需要）。

运行环境需满足：
- 对知识库目录（vault）有文件读写权限
- Python 3 + scikit-learn（重复检测时）

验证安装：先完成 setup 选定 vault，再对 Agent 说「帮我初始化一个知识库」，应触发 setup-wizard 模式。开源前请再跑 `python3 scripts/validate_skills.py && python -m pytest -v`，并用仓库内 `tests/EVAL.md` 做行为评测。

## 三、日常使用（三个模式）

### 模式一：初始化（一次性）

**触发说法**：「帮我初始化一个知识库」「搭建 wiki」

Agent 会做的事情：
1. 对你进行三轮访谈（约 10 分钟，一次最多 3 个问题）——目标是生成"宪章"（知识库的最高判断标准）
2. 生成宪章草稿 → **你确认修改后**才落盘（这一步必须参与，北极星只有你能定）
3. 创建目录结构：`00_系统/`（大脑）、`10_inbox/`（入口）、`20_领域/`（笔记）、`90_archive/`（归档）；确认 Atlas 分区后，在 `20_领域/<分区名>/` 建一层收纳文件夹（MOC 管导航，文件夹管收纳）
4. 倒入旧文档时执行批量吸附——**这是最有价值的一步**：乱文档一天变有序库，同时积累首批决策日志

**你要做的**：回答访谈、确认宪章、批量审批合并建议（人话卡片形式，三选一）。

### 模式二：吸附（日常高频）

**触发说法**：无需特意触发——往 `10_inbox/` 丢内容后说「整理一下 inbox」即可

流程：Agent 判断内容属于哪个域 → 找挂载位置 → 判定与已有笔记的关系 → 给你一张人话卡片：

```
《示例笔记标题》
和库里的《已有相关笔记》有 87% 重复。
建议：合并进旧笔记，你新写的两段独有内容会保留。
[同意]  [保留两篇]  [我有别的想法]
```

（示例里的技术主题仅作演示；你的库可以是任意领域。）

初期所有决策都需你批准（种子期，约 2 周）；随着你持续批准，Agent 会提议对纯文本操作放权。

### 模式三：园艺（双周定期）

**触发说法**：「给知识库做个体检」「感觉库有点乱」；建议配合定时提醒双周触发一次

Agent 会扫描：重复内容（跑 `dup_scan.py`）、过时内容（比对域档案的版本锚点）、方向漂移（各域增长 vs 宪章北极星），然后输出人话摘要：

```
花园巡查
- 发现 3 组内容重复，建议合并
- 2 篇笔记相对域档案锚点已过时
- 某核心域三周没新内容——是计划如此吗？
[逐个处理]  [只看重复的]  [全部忽略]
```

**合并、归档、拆分永远需要你批准**（L3 铁律，不放权）。

## 四、后续调优指南

skill 的价值靠迭代释放。以下是预期中的调优点，按出现概率排序。

### 1. 访谈问题措辞（初始化阶段）

**症状**：小白用户答不上来，或回答太泛导致宪章空洞。
**改法**：编辑 `references/setup-wizard.md` 第 2 节的问题清单——把开放题改成选择题、增加"举例"类问题（人说不清品味但展示得出）。每次遇到答不上来的问题，记录并改写该题。

### 2. 相似度阈值（园艺阶段）

**症状 A**：明显重复的笔记没被抓出来 → 阈值偏高，调低。
**症状 B**：不相干的笔记被误判重复 → 阈值偏高场景是短笔记，或调高阈值。
**改法**：`gardening.md` 中 `dup_scan.py` 的 `--threshold` 默认 0.7，按你的语料实测调整；判定边界（0.85/0.95 两档）同理可调。建议用真实库跑 2–3 期审计后再定。

### 3. 宪章过薄（使用 2–4 周后）

**症状**：Agent 的判断频繁被你推翻，且推翻理由总是同一类。
**改法**：这不是 Agent 笨，是规则没写出来。每次复盘时把"你实际的标准"补进 `00_系统/宪章.md`，宪章从一页纸慢慢变厚是**正常的进化路径**——决策日志里的拒收记录是最锋利的素材。

### 4. 放权节奏（使用 4–8 周）

**症状**：审批点太多觉得烦，或放权后出现错误执行。
**改法**：`references/autonomy.md` 的放权线默认 approve 率 85% + 稳定 2 周。觉得烦说明达标了，接受放权提议；放权后出错 2 次会自动降级——如果你想更保守，调高到 90%。**L3（合并/归档/拒收/拆分）不建议对任何人放权**，这不是技术问题是责任问题。

### 5. 域档案缺失（多领域用户）

**症状**：某领域内容的事实判断不靠谱（如把过时 API 当有效的）。
**改法**：该域笔记满 5 篇后，用 `assets/templates/domain-pack.md` 在 `00_系统/domains/` 建档——重点填"时效性锚点"（当前版本号）和"Smell 清单"（该领域常见错误模式）。域档案质量直接决定事实核验质量，且须随版本更新维护。

### 6. 指标评分锚点（长期）

**症状**：诊断单里的指标得分和你的体感不符。
**改法**：`references/intake.md` 第 3 节的评分锚点是通用起点。用 20–30 条决策日志对照你的审批结果，校准哪条锚点描述偏离了你的判断习惯，直接改锚点描述。

### 7. 新增领域/新用户（推广时）

- **新领域**：不需要改 skill，域知识全部走 `00_系统/domains/` 档案文件，skill 会自动路由
- **新用户**：直接给 `.skill` 文件 + 本文档。每个用户的个性化发生在 vault 的宪章和日志里，skill 本体保持不变——这是"一套 skill，千人千库"的设计意图

## 五、边界与注意事项

| 事项 | 说明 |
|---|---|
| 定时园艺 | skill 本身是触发式的，"双周提醒"需靠工具的定时任务/提醒功能兜底 |
| 大型库性能 | 笔记超过 ~2000 篇时 `dup_scan.py` 全量两两比对会变慢，届时可按域分目录扫描 |
| 纯文字润色 | 不在本 skill 职责内——它只做诊断和结构决策，润色请配合编辑类 skill（如 edit-article） |
| 归档安全 | `90_archive/` 永不自动删除，误合并可从归档找回 + 查决策日志还原 |
| 多设备同步 | vault 是普通 Markdown 目录，可用 Git / iCloud / Obsidian Sync 任意方案，与 skill 无关 |

## 六、版本迭代建议

v1.1 → v1.2 最可能的修改点（按优先级）：
1. 访谈问题清单（根据首批小白用户的卡壳反馈）
2. 相似度阈值与判定边界（根据真实语料实测；先跑 `tests/fixtures/sample-vault`）
3. 人话卡片文案（根据用户审批时的犹豫点）

修改 skill 本体后跑 `scripts/validate_skills.py` + `pytest`，push 到 GitHub；用户侧执行 `npx skills@latest update -g -y` 即可跟上。Desktop 用户再跑 `./scripts/pack_skills.sh` 重新上传。vault 内的宪章、日志、域档案属于用户资产，**不随 skill 升级覆盖**。
