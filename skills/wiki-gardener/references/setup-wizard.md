# 初始化向导（Setup Wizard）

知识库冷启动流程。目标：用户零专业知识、15 分钟内完成初始化，并获得"哇时刻"。

## 目录

0. 第零轮：Persona 识别
1. 流程总览
1.1 已有乱库接入（非空 vault）
2. 访谈问题清单
3. 宪章生成规则
4. 目录初始化
5. 批量吸附（历史文档）
6. 初始化验收

---

## 0. 第零轮：Persona 识别

在正式访谈前执行。目的：用预设 persona 把 15 分钟访谈压缩到 5 分钟。

1. 列出 `assets/personas/` 中的可用 persona（文件名即选项），加"都不像，自定义"：
   「这个库主要给谁用——我先猜个大概，你来纠正：独立老师 / …… / 都不像」
2. 用户选中 persona 后，读取对应文件，执行替换：
   - **预填项降级为确认题**：收录/排斥标准种子展示给用户——「这类库通常收 xx、不收 xx，你一样吗？哪里不一样？」
   - **北极星给候选句**：展示 persona 的北极星候选，「改成你的说法，一句话」——**必须用户亲口确认才落盘，persona 只给候选**
   - **协作边界确认**：若 persona 有「协作边界种子」表，逐项问清（学段/栈/主战场等），答案写入对应域档案锚点或宪章旁注——**不写死在 skill 里**
   - **访谈题替换**：用 persona 的访谈变体替换第二轮对应问题
   - **推荐初始域**：列出 persona 推荐的域，逐个问「这个现在要吗？」，要的用 `assets/domain-seeds/` 对应种子在 `00_系统/domains/` 建档（注意：基础域默认加载，运营类域有实际动作才建）
   - **推荐 Atlas 分区**：把 persona「推荐 Atlas 分区」表预填进 `00_系统/atlas/总MOC.md` 的「主题分区」（分区名可改）；用户确认后，在 `20_领域/<分区名>/` **各建一层空文件夹**作初始收纳（与 MOC 分区同名）。禁止 `01-xxx` 编号目录，禁止默认多层嵌套。域档案（`00_系统/domains/`）仍按需加载，不随每个文件夹自动建档
   - **顾问团告知**：一句话告诉用户可用的专家身份及召唤方式（「以后说『以 xx 专家的身份』即可」）
3. 用户选"自定义"→ 跳过 persona，走完整三轮访谈（第 2 节）
4. 选中 persona 后访谈压缩为：北极星确认（必做）→ 收录标准确认（改错题）→ 协作边界确认 → 第三轮习惯题（不变）

红线：persona 是种子不是笼子。用户确认时改掉的每处预填，都是他的真实品味——如实落盘，不用 persona 原文覆盖用户表述。

## 1. 流程总览

```
第零轮 persona 识别（约 1 分钟）
→ 访谈（确认题为主，5–10 分钟）→ 生成宪章草稿 → 用户确认修改
→ 创建目录结构与资产（含加载域种子）→ 批量吸附历史文档（如有）
→ 输出初始化摘要 + 首批决策日志
```

核心原则：**让用户做选择题和改错题，绝不让用户面对空白页**。所有生成物先出草稿，用户只改不写。

## 1.1 已有乱库接入（非空 vault）

用户说「我已有笔记库，只是很乱，想用你们 skill 管以后」时走本分支——**不是空库冷启动**。用户向说明见仓库 `docs/已有知识库接入.md`。

### 探测

- 目录里已有大量 `.md`，但可能没有 `00_系统/宪章.md` / `10_inbox/`  
- 或已有 Obsidian 结构，只是未按本 skill 约定分层  

### 必做（顺序）

1. **先备份提醒**：动目录前请用户确认已备份或 git 提交；**禁止**静默删除用户旧文件  
2. **访谈与宪章照常**（第零轮 + 确认题）——规矩先于搬家  
3. **就地脚手架**：在用户指定的现有根目录创建缺失的 `00_系统/`、`10_inbox/`、`20_领域/<分区>/`、`90_archive/`；已存在的同名约定目录则复用、不覆盖用户宪章（若用户要从头写宪章须明确确认）  
4. **旧内容策略（三选一，问清再动）**：  
   - **全量漏斗**：待纳入旧文 → `10_inbox/` → 本节第 5 节批量吸附  
   - **分批漏斗（默认推荐）**：本周只搬一类主题进 inbox；其余旧路径暂留，标明「尚未吸附」  
   - **就地登记**：少数已确认的优质篇，经用户批准后迁入 `20_领域/<分区>/` 并挂 MOC（仍写诊断单与日志；禁止整树自动「宣布合规」）  
5. 批量吸附规则同第 5 节；**相关补缺新建互链**，勿因主题相近硬 merge（见 `intake.md`）  
6. 首轮批量以结构为主；不必对每一旧篇先跑 domain-expert（高价值/明显错的再审）

### 红线

- 不把用户未进 inbox、未批准的旧文当成已过吸附的正本  
- 不一次无人值守处理数百篇而不出汇总卡片  
- 完成后告知：日常新内容只进 `10_inbox/`；旧债用分批吸附 + 园艺还清  

## 2. 访谈问题清单

按顺序提问，一次不超过 3 个问题，全程人话，不暴露"宪章""域"等术语：

**第一轮（目标）：**
1. 这个知识库主要帮你解决什么问题？（随意说，一两句人话即可）
2. 你以前用笔记软件最受不了什么？（选项：找不到东西 / 重复堆叠 / 信息过时 / 越记越乱 / 其他）
3. 三年后，这个库变成什么样你会觉得"值了"？

**第二轮（品味校准）：**
4. 发我 2–3 个你最近想收进库里的内容（链接、文档、想法都行）
5. 有什么内容是你绝对不想要它出现在库里的？举 1–2 个例子
6. 你记笔记更偏向哪种？（选项：原文摘录为主 / 自己理解重写为主 / 混合）

**第三轮（习惯）：**
7. 你大概多久会往里丢一次东西？希望它自动整理到什么程度？
8. 涉及哪些主题领域？（用于判断初始域，但**此时不建域文件夹**）

## 3. 宪章生成规则

从访谈回答生成 `00_系统/宪章.md`（模板见 `assets/templates/constitution.md`）：

| 回答来源 | 映射到宪章 |
|---|---|
| Q1 + Q3 | 北极星（压缩成一句话，保留用户原话关键词） |
| Q4（想收的例子） | 收录标准：归纳例子的共性，写成 2–3 条可执行判断 |
| Q5（排斥的例子） | 排斥标准：归纳共性，如"网上能搜到的纯工具文档不复制" |
| Q6 | 好笔记定义中的写法偏好（摘录比例、重写要求） |
| Q2 | 转化为度量重点（怕重复 → 冗余率权重高；怕过时 → 腐烂扫描频率高） |
| Q7 | 吸附自动化建议级别 + 园艺频率 |

**Q2 → 度量重点（必须对齐，供评测指纹使用）：**

| 用户选项 | 度量重点应强调 |
|---|---|
| 找不到东西 | 孤儿率 / 挂载与 MOC 完整度 / 可检索性 |
| 重复堆叠 | 冗余率 / 合并质量 |
| 信息过时 | 腐烂扫描 / 时效性锚点 |
| 越记越乱 | 孤儿率 / 结构与挂载完整性 |

**Q6 → 写法偏好：** 摘录为主 / 重写为主 / 混合——原样写入「好笔记的定义」。

**风格可区分性：** 不同访谈答案必须产出可区分的宪章（北极星关键词、收/斥标准、度量重点不得套模板空话）。校准样例与自动评分见 `tests/fixtures/interview-personas/` 与 `scripts/score_constitution.py`。

生成后向用户复述一遍："我从你说的里提炼出这些标准，对吗？"——**用户确认后才落盘**。北极星必须用户亲口认可，不可全自动。

**红线补充：** Q8 提到的主题只记入访谈纪要或总 MOC 候选分区，**此时不按 Q8 关键词批量建文件夹、不预建域档案**；分区名须用户确认后再在 `20_领域/` 建一层目录。域档案等内容长出来。

## 4. 目录初始化

按以下结构创建（用 `assets/templates/` 中的模板填充）：

```
vault/
├── 00_系统/
│   ├── 宪章.md            # 访谈生成
│   ├── atlas/总MOC.md      # moc.md 模板（主题分区与下方文件夹对齐）
│   ├── 决策日志/           # 空目录，附 decision-log.md 模板说明
│   └── domains/           # 按需放入已确认的域种子；勿与 20_领域 子文件夹一一强绑
├── 10_inbox/
├── 20_领域/
│   ├── <分区A>/           # 与总 MOC 主题分区同名，一层即可
│   └── <分区B>/
└── 90_archive/
```

红线：
- **要做**：用户确认 Atlas / 总 MOC 分区后，创建 `20_领域/<分区名>/` 一层空文件夹，吸附时笔记优先落入对应分区
- **不做**：按 Q8 随口提到的每个词批量建夹；建 `01-课程体系/` 类编号深树；默认两层以上嵌套；把每个文件夹自动建成一份 `domains/*.md`
- 域档案（判断知识）仍按开域条件生长，与收纳文件夹解耦
- 不写用户没确认过的宪章条目
- 在总 MOC 顶部写一句人话使用说明："往里丢东西到 10_inbox 即可；整理后进 20_领域 对应分区"

## 5. 批量吸附（历史文档 / 已有库迁入）

用户倒入旧文档或从已有乱库迁入 `10_inbox/` 时（这是哇时刻，务必做好）：

1. 全部（或本批）放入 `10_inbox/`
2. 逐份走吸附流程（见 `intake.md`），批量模式下的简化：
   - 高置信度（≥ 0.8）的新建决策直接执行并批量报备
   - 合并/拒收/拆分决策**汇总成一批人话卡片**，让用户一次性过：「以下 5 组内容重复，建议合并：[逐组列出，每组一行理由] 全部同意？/ 逐条看？」
   - **相关补缺**（同主题族、不同原子结论）单独列出：建议新建并互链，不要混进「合并」组
3. 全部决策写决策日志——这批日志是种子期训练数据，理由栏认真写
4. 生成/更新 Atlas：按吸附结果归纳主题簇，更新总 MOC；笔记落入已确认的 `20_领域/<分区>/`（无匹配分区则暂放 `20_领域/_未归类/` 并提示用户归入或新增分区）
5. 分批模式下：本批结束后提醒「旧堆还剩未搬文件时可继续搬进 inbox」

完成后输出摘要：「本批 X 份 → 保留 Y 篇原子笔记，合并 Z 组，相关补缺新建 W 篇，拒收 N 份（理由见日志）」。

## 6. 初始化验收

向用户确认以下全部成立才算完成：
- [ ] persona 已识别（或确认走自定义路径），预填项经用户逐条确认
- [ ] 协作边界（若有）已确认并写入域档案锚点或宪章，非 skill 原文硬贴
- [ ] 用户选择的域种子已在 `00_系统/domains/` 建档，时效性锚点已请用户填写
- [ ] 总 MOC 已按确认后的 Atlas 分区建好主题骨架；且 `20_领域/<分区名>/` 一层文件夹已与之对齐（无 `01-xxx` 编号深树）
- [ ] 宪章已确认落盘，用户看过且认可
- [ ] 目录结构创建完毕，10_inbox 可用
- [ ] 总 MOC 存在且能反映当前内容结构
- [ ] 历史文档（如有）已全部处理，inbox 清空
- [ ] 决策日志 ≥ 实际处理数，理由栏非空
- [ ] 用户知道日常用法：「往 10_inbox 丢，有疑问我会来问你」
