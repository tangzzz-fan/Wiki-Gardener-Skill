# Persona：独立老师

> 适用画像：脱离机构或兼职独立授课的老师（幼小衔接 / 小初高学科 / 素养课等），
> 需要自己招生、自己设计课程、自己做内容运营，时间碎片化。
> 用法：setup-wizard 第零轮选中本 persona 后，以下预填项全部降级为"确认题"——
> 展示给用户改，而不是让用户从零写。**北极星必须用户亲口确认，persona 只给候选。**
>
> AI 默认扮演**教研助手**：协助备课、出题、学情诊断、家长反馈与经营文案；
> **不替代老师做最终教学决策**。学科边界（学段/教材/课标）在初始化时问清，写入域档案，不写死在本 skill。

## 北极星候选（供用户修改）

- 「三年后这个库是我的课程资产库：每一节课、每一次招生、每一条爆款视频都能从里面长出来」
- 「这个库替我记得所有教学决策的依据，我只需要上课和判断」

## 协作边界种子（写入域档案 / 宪章，须用户确认）

初始化时逐条确认，答案写入 `domains/课程设计.md` 时效性锚点与局部宪章（示例口径，勿默认当成初中数学）：

| 项 | 候选问法 | 落盘位置 |
|---|---|---|
| 学段 | 「你主要教哪些学段/年级？」 | 课程设计 · 时效性锚点 |
| 教材与课标 | 「默认教材版本？课标依据？」 | 课程设计 · 时效性锚点 |
| 授课形态 | 「一对一 / 小班人数上限 / 班课？」 | 课程设计 · 局部宪章 |
| 服务边界 | 「课时外答疑、测验、家长沟通频率怎么定？」 | 招生 · 局部宪章 |
| AI 权限 | 确认：「助手只给草案，教学决策你拍板」 | 宪章 · 好笔记的定义旁注 |

## 收录标准种子

- 收：家长真实反馈与转化记录（一句话聊天记录也算——这是最锋利的资产）
- 收：自己的教案迭代、课堂复盘（哪怕是失败的）
- 收：题与练的设计（含答案、解析、易错点；有难度分层更好）
- 收：学情记录（错题类型、正确率、时间、态度——先事实后判断）
- 收：同行/竞品的拆解笔记（必须带自己的判断，不是搬运）
- 收：招生数据与漏斗记录（体验课到场率、转化率、续费率）
- 不收：网上能搜到的通用教学法理论（教材上有的是，不复制）
- 不收：未验证的"爆款技巧"搬运（没有自己实操数据佐证的一律标 [警告]）
- 不收：政策灰色地带的"玩法"（合规是红线，见招生域档案）
- 不收：承诺「保分 / 包过」类话术与材料；不收虚构或可识别的学生隐私细节

## 笔记类型模板

- **教案卡**（默认结构）：
  1. 学情假设与目标（知识 / 能力 / 习惯，可观测）
  2. 重难点与突破策略
  3. 课堂流程（时间分配；标明课时时长）
  4. 例题 + 变式 + 当堂练
  5. 作业分层（基础 / 巩固 / 挑战）
  6. 课后复盘要点（给老师自己）
- **题目卡**：题干 / 答案 / 解析 / 易错点 / 难度分层 / 题型（理解·应用·综合·压轴等，按学科改）
- **学情卡**：先事实（错题类型、正确率、用时、态度）→ 再判断 → 可执行建议（下次练什么、家长可配合什么）
- **家长沟通卡**：事实摘要 / 建议 / 语气自检（专业平和具体；禁「很差」「不行」等标签）
- **学员反馈记录**：原话摘录 / 场景 / 可转化的卖点 / 待改进点
- **选题卡**：钩子 / 目标家长痛点 / 对应课程卖点 / 数据回填位
- **制作指导卡**（短视频编导）：主选形式（图文/口播/出镜…）/ 取舍理由 / 结构与拍摄清单 / 服务指标 / 验证设计
- **数据复盘**：发布内容 / 核心指标 / 归因猜测 / 下一步动作

学科书写细则（公式语法、星级难度等）在用户确认教材与学科后，写入课程设计域的「写作立场」，persona 不写死某一科。

## 访谈变体（第零轮选中后替换默认问题）

- Q4 替换为：「发我一两条你想留住的家长反馈，或者一份你的教案片段」
- Q5 替换为：「招生和做内容时，有没有什么是你坚决不想做的？（比如：不想露脸 / 不想低价内卷 / 不想做学科类擦边 / 绝不承诺保分）」
- Q7 追加：「你的时间主要碎在哪些环节？备课 / 招生 / 剪视频 / 家长沟通？」——答案决定 inbox 摩擦要降到多低
- Q8 追加确认：「学段、教材版本、一对一还是小班？」——写入协作边界，不建文件夹

## 度量权重

- 重点盯 **inbox 滞留**（老师时间碎，入口必须零摩擦，滞留 > 3 天就是入口设计失败）
- 其次盯 **孤儿率**（教案和反馈如果挂不进课程结构 / 总 MOC 分区，等于白记）

## 专家顾问团（辅助身份映射表）

> 以下身份不是独立 Agent，是挂在各域档案上的"专家立场"（见各域档案的「专家立场」节）。
> domain-expert 在该域执笔/审查时读取立场，即成为该专家。召唤方式：对 Agent 说
> 「以 xx 专家的身份……」并确保对应域档案已加载。

| 场景 | 召唤身份 | 立场存放处 |
|---|---|---|
| 设计/审查课程、教案、课程体系 | 学而思课程设计专家团队 | `domains/课程设计.md` |
| 招生策略、转化漏斗、体验课设计 | 学而思资深招生专家 | `domains/招生.md` |
| 抖音推流、指标、合规、数据复盘 | 熟谙抖音流量算法的运营专家 | `domains/抖音运营.md` |
| 视频形式决策与怎么拍（图文/口播/出镜） | 资深短视频编导 | `domains/短视频编导.md` |

> 协作顺序：选题先过运营专家审核（该不该发、追什么指标），通过后移交编导（怎么拍）。
> **存在性先于形态性**——审核未通过的选题不进入制作指导。
