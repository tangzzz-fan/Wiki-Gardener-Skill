# Persona：自媒体工作者

> 适用画像：以内容为主业的创作者（图文 / 短视频 / 多平台分发），
> 选题焦虑是日常，数据复盘是命脉，平台规则追着人跑。
> 用法：setup-wizard 第零轮选中本 persona 后，预填项降级为确认题——
> 展示给用户改，而不是让用户从零写。**北极星必须用户亲口确认，persona 只给候选。**

## 北极星候选（供用户修改）

- 「三年后这个库是我的选题与方法论资产库：不再选题焦虑，每个爆款都有可复制的依据」
- 「这个库记得我每次内容实验的结果，让运气变成概率」

## 收录标准种子

- 收：自己的选题卡与数据复盘（失败的内容同样收——负样本最值钱）
- 收：爆款拆解（必须拆到"为什么成立"的结构层，不是"这条火了"的感慨）
- 收：平台规则变化的实测记录（含日期——运营知识半衰期极短）
- 收：自己的文案/脚本原稿与修改痕迹（修改理由是核心资产）
- 不收：网上搬运的"运营技巧"合集（无自己数据佐证的一律标 [警告]）
- 不收：热点流水账（追过的热点没有沉淀为方法论的，不留）
- 不收：他山之石类的截图囤积（"这个不错先存着"是收藏夹癌症）

## 推荐初始域

| 域 | 性质 | 说明 |
|---|---|---|
| 内容创作 | 基础域（默认加载） | 用 `domain-seeds/内容创作.md` 建档 |
| 抖音运营 | 按需加载（共享域） | 做抖音才建，用 `domain-seeds/抖音运营.md` |
| 短视频编导 | 按需加载（共享域） | 要定形态/怎么拍时建，用 `domain-seeds/短视频编导.md` |
| 小红书运营 | 按需加载（共享域） | 做小红书才建，用 `domain-seeds/小红书运营.md` |

## 笔记类型模板

- **选题卡**：选题 / 目标人群痛点 / 钩子 / 平台适配 / 数据回填位
- **爆款拆解卡**：原内容 / 结构拆解（钩子-留存-转化）/ 可复制点 / 我的改造方案
- **数据复盘卡**：发布内容 / 核心指标 / 归因猜测（显式标注是猜测）/ 下一步实验
- **脚本迭代卡**：原稿 / 修改 / 修改理由 / 发布后数据验证

## 推荐 Atlas 分区（总 MOC + `20_领域` 一层文件夹）

> 确认分区名后：总 MOC 与 `20_领域/<分区名>/` 同步建立。禁止编号深树与默认多层嵌套。

| MOC 分区 / 文件夹名 | 放什么 |
|---|---|
| 选题库 | 选题卡、痛点与钩子库 |
| 脚本与文案 | 原稿、改稿、修改理由 |
| 制作指导卡 | 形式选型、拍摄清单（短视频编导域产物） |
| 发布复盘 | 数据复盘、负样本 |
| 爆款拆解 | 结构拆解与可复制点 |
| 平台规则 | 带日期的规则实测（易腐烂） |

命名约定候选：`平台-日期或期数-主题.md`（放入对应分区文件夹）。

## 协作边界种子（须用户确认）

| 项 | 候选问法 | 落盘 |
|---|---|---|
| 主战场 | 「主平台是？是否多平台分发？」 | 对应运营域 · 局部宪章 |
| 人设红线 | 「坚决不做的内容类型？」 | 宪章 · 排斥标准 |
| AI 权限 | 确认：助手出草案与拆解，发布决策你拍板 | 宪章旁注 |

## 访谈变体（第零轮选中后替换默认问题）

- Q4 替换为：「发我一条你做过的最满意的内容（或复盘），和一条你想不通为什么扑了的」
- Q5 替换为：「你的内容领域里，有什么是你坚决不做的？（比如：不追某类热点 / 不做某类标题党 / 不露脸）」
- Q7 追加：「你主战场是哪个平台？更新频率多少？」——决定加载哪个运营域种子

## 度量权重

- 重点盯 **腐烂扫描**（平台规则月度级变化，运营知识过期即误导）
- 其次盯 **inbox 滞留**（创作灵感转瞬即逝，入口慢一天就丢选题）

## 专家顾问团（辅助身份映射表）

> 以下身份不是独立 Agent，是挂在各域档案上的「专家立场」。
> domain-expert 在该域执笔/审查时读取立场，即成为该专家。召唤方式：对 Agent 说
> 「以 xx 专家的身份……」并确保对应域档案已加载。

| 场景 | 召唤身份 | 立场存放处 |
|---|---|---|
| 选题、脚本结构、跨平台内容方法论 | 资深爆款内容操盘手 | `domains/内容创作.md` |
| 抖音推流、指标、合规、数据复盘 | 熟谙抖音流量算法的运营专家 | `domains/抖音运营.md` |
| 视频形式决策与怎么拍（图文/口播/出镜） | 资深短视频编导 | `domains/短视频编导.md` |
| 小红书笔记、种草、搜索流量 | 小红书种草运营专家 | `domains/小红书运营.md` |

> 协作顺序：选题先过运营专家审核（该不该发、追什么指标），通过后移交编导（怎么拍）。
> **存在性先于形态性**——审核未通过的选题不进入制作指导。
