# Persona：全栈工程师

> 适用画像：前后端通吃的工程师（独立开发者 / 小团队技术负责人 / 全栈岗），
> 技术决策链路长，一个人扛从数据库到页面，知识跨度大、遗忘速度快。
> 用法：setup-wizard 第零轮选中本 persona 后，预填项降级为确认题——
> 展示给用户改，而不是让用户从零写。**北极星必须用户亲口确认，persona 只给候选。**

## 北极星候选（供用户修改）

- 「三年后这个库是我的第二大脑：任何技术决策都能查到当时的依据，任何坑只踩一次」
- 「这个库沉淀我所有的架构判断，而不是搜索引擎能给我的东西」

## 收录标准种子

- 收：自己项目的架构决策记录（ADR：上下文 / 选项 / 决策 / 代价）
- 收：线上事故与踩坑复盘（含时间线、根因、止血与根治）
- 收：技术调研对比（带自己验证过的结论，不是文档翻译）
- 收：能**深入本质**的笔记——用**第一性原理**拆到约束与机制（不只记「怎么做」，还要写清「为什么只能这样 / 哪条物理或工程约束决定了取舍」）
- 不收：官方文档的抄写（链接即可，内容不复制）
- 不收：没跑过代码就信的"最佳实践"搬运
- 不收：与自己做过的技术栈完全无关的泛泛趋势文
- 不收：只有步骤/术语清单、未追问本质的操作备忘（工程师库拒绝「伪知识堆积」）

## 推荐初始域

| 域 | 性质 | 说明 |
|---|---|---|
| 架构设计 | 基础域（默认加载） | 用 `domain-seeds/架构设计.md` 建档 |
| 后端开发 | 按需加载 | 用 `domain-seeds/后端开发.md` |
| 前端开发 | 按需加载 | 用 `domain-seeds/前端开发.md` |

## 笔记类型模板

> 工程师笔记底线：每张卡至少有一句「本质/约束」层——用第一性原理回答「为什么」，禁止只留步骤。

- **ADR 决策卡**：上下文 / 选项对比 / 决策与理由 / 代价与回退方案 / **第一性原理一句**（决定取舍的那条硬约束）
- **事故复盘卡**：时间线 / 根因 / 止血动作 / 根治动作 / 监控改进（根因须拆到机制，不只归咎「人疏忽」）
- **踩坑卡**：现象 / 环境版本 / 根因 / 解法 / 可复用检查项
- **技术调研卡**：需求约束 / 候选方案 / 实测数据 / 结论与适用边界

## 推荐 Atlas 分区（总 MOC + `20_领域` 一层文件夹）

> 确认分区名后：总 MOC 与 `20_领域/<分区名>/` 同步建立。禁止编号深树与默认多层嵌套。

| MOC 分区 / 文件夹名 | 放什么 |
|---|---|
| 架构与 ADR | 系统设计、选型决策、被否决的选项 |
| 事故与稳定性 | 线上事故、止血与根治 |
| 踩坑与环境 | 版本绑定的坑与检查项 |
| 调研与对比 | 带实测的技术调研 |
| 工程化与发布 | CI、观测、发布与回滚（有则挂） |

命名约定候选：`主题-结论关键词.md` 或 `ADR-短标题.md`（放入对应分区文件夹）。

## 协作边界种子（须用户确认）

| 项 | 候选问法 | 落盘 |
|---|---|---|
| 主力栈 | 「前端 / 后端 / 数据 / 云各用什么？」 | 对应域 · 时效性锚点 |
| 决策权 | 「库是个人第二大脑还是团队共享？」 | 宪章 |
| AI 权限 | 确认：助手给方案与审查，上线决策你拍板 | 宪章旁注 |

## 访谈变体（第零轮选中后替换默认问题）

- Q4 替换为：「发我一篇你最近想留住的踩坑记录或技术决策片段——最好能说到本质，而不只是步骤」
- Q5 替换为：「有没有什么是你觉得不值得记的？（比如：官方文档摘录 / 某类框架的八股文 / 未用第一性原理想过的『最佳实践』）」
- Q7 追加：「你的主要技术栈是什么？前端 / 后端 / 数据库 / 云，各用什么？」——答案决定加载哪些域种子与术语表校准

## 度量权重

- 重点盯 **腐烂扫描**（技术版本迭代快，过期建议比重复更危险）
- 其次盯 **冗余率**（工程师爱重复记录同一问题的不同侧面）
- 抽查笔记是否仍停留在步骤层：若连续多篇缺少「为什么/约束」句，视为品味漂移，初始化确认时提醒用户

## 专家顾问团（辅助身份映射表）

> 以下身份不是独立 Agent，是挂在各域档案上的「专家立场」。
> domain-expert 在该域执笔/审查时读取立场，即成为该专家。召唤方式：对 Agent 说
> 「以 xx 专家的身份……」并确保对应域档案已加载。

| 场景 | 召唤身份 | 立场存放处 |
|---|---|---|
| 架构选型、系统设计评审 | 资深架构评审委员会 | `domains/架构设计.md` |
| 后端方案、性能与稳定性 | 资深后端架构师 | `domains/后端开发.md` |
| 前端方案、工程化 | 资深前端专家 | `domains/前端开发.md` |

> 备注：全栈工程师做独立开发/技术自媒体时，可叠加加载共享运营域种子（抖音运营 / 短视频编导 / 小红书运营 / 内容创作），persona 不捆绑，按需组合。流程：**存在性先于形态性**——算法运营专家审完 → 短视频编导出怎么拍。
