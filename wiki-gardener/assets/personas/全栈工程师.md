# Persona：全栈工程师

> 适用画像：前后端通吃的工程师（独立开发者 / 小团队技术负责人 / 全栈岗），
> 技术决策链路长，一个人扛从数据库到页面，知识跨度大、遗忘速度快。
> 用法：setup-wizard 第零轮选中本 persona 后，预填项降级为确认题——
> 展示给用户改，而不是让用户从零写。**北极星必须用户亲口确认，persona 只给候选。**

## 北极星候选（供用户修改）

- 「三年后这个库是我的第二大脑：任何技术决策都能查到当时的依据，任何坑只踩一次」
- 「这个库沉淀我所有的架构判断，而不是搜索引擎能给我的东西」

## 收录标准种子

- 收：自己项目的架构决策记录（ADR：上下文 / 选项 / 决策 / 代价）
- 收：线上事故与踩坑复盘（含时间线、根因、止血与根治）
- 收：技术调研对比（带自己验证过的结论，不是文档翻译）
- 不收：官方文档的抄写（链接即可，内容不复制）
- 不收：没跑过代码就信的"最佳实践"搬运
- 不收：与自己做过的技术栈完全无关的泛泛趋势文

## 推荐初始域

| 域 | 性质 | 说明 |
|---|---|---|
| 架构设计 | 基础域（默认加载） | 用 `domain-seeds/架构设计.md` 建档 |
| 后端开发 | 按需加载 | 用 `domain-seeds/后端开发.md` |
| 前端开发 | 按需加载 | 用 `domain-seeds/前端开发.md` |

## 笔记类型模板

- **ADR 决策卡**：上下文 / 选项对比 / 决策与理由 / 代价与回退方案
- **事故复盘卡**：时间线 / 根因 / 止血动作 / 根治动作 / 监控改进
- **踩坑卡**：现象 / 环境版本 / 根因 / 解法 / 可复用检查项
- **技术调研卡**：需求约束 / 候选方案 / 实测数据 / 结论与适用边界

## 访谈变体（第零轮选中后替换默认问题）

- Q4 替换为：「发我一篇你最近想留住的踩坑记录或技术决策片段」
- Q5 替换为：「有没有什么是你觉得不值得记的？（比如：官方文档摘录 / 某类框架的八股文）」
- Q7 追加：「你的主要技术栈是什么？前端 / 后端 / 数据库 / 云，各用什么？」——答案决定加载哪些域种子与术语表校准

## 度量权重

- 重点盯 **腐烂扫描**（技术版本迭代快，过期建议比重复更危险）
- 其次盯 **冗余率**（工程师爱重复记录同一问题的不同侧面）

## 专家顾问团（辅助身份映射表）

| 场景 | 召唤身份 | 立场存放处 |
|---|---|---|
| 架构选型、系统设计评审 | 资深架构评审委员会 | `domains/架构设计.md` |
| 后端方案、性能与稳定性 | 资深后端架构师 | `domains/后端开发.md` |
| 前端方案、工程化 | 资深前端专家 | `domains/前端开发.md` |

> 备注：全栈工程师做独立开发/技术自媒体时，可叠加加载共享运营域种子（抖音运营 / 小红书运营 / 内容创作），persona 不捆绑，按需组合。
