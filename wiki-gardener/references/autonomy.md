## 1. 自治阶梯详解

| 级别 | 操作 | 放权条件 | 放权后行为 |
|---|---|---|---|
| L0 种子期 | 一切操作 | 新 vault 默认 | 出诊断单 → 等批准 |
| L1 | rewrite / compress | 该类 approve 率 > 85% 且稳定 2 周 | 直接执行 + 事后报备摘要 |
| L2 | 新建原子笔记、correct | L1 稳定 ≥ 2 周且抽检无错 | 直接执行 + 报备 |
| L3 | split / merge / 迁移 / 归档 / 拒收 | **永不放权** | 永远人工批准 |

升降级都可逆：某级别出现 2 次错误执行 → 降回上一级并在日志记录原因。

放权状态持久化在 `00_系统/atlas/自治状态.md`，每次达标检查更新。

## 2. 放权检查流程

每次园艺审计时顺带执行：
1. 统计决策日志中各操作类型的 approve 率（近 2 周窗口）
2. 达到放权线 → 向用户提议：「过去两周我的改写建议你 90% 都同意了，以后这类我可以直接做、做完告诉你，行吗？」
3. 用户同意后更新自治状态文件
4. 放权后每次执行在当周摘要中报备（做了什么、为什么），用户可一键撤销

## 3. 健康度量指标

双周记录到 `00_系统/atlas/健康基线.md`，与上期对比看趋势：

| 指标 | 计算 | 健康方向 |
|---|---|---|
| approve 率 | 批准的诊断单 / 总诊断单（按操作类型分） | ↑（放权线 85%） |
| 冗余率 | 相似度 > 0.8 的笔记对 / 总笔记数 | ↓ |
| 孤儿率 | 零入链笔记 / 总笔记数 | ↓（< 10%） |
| inbox 滞留时长 | 进 inbox 到完成吸附的平均天数 | ↓（< 3 天） |
| 熵减趋势 | 本期合并+归档数 vs 新增数 | 增长伴随定期收缩 |
| 复盘闭环率 | 判错案例中已归因并回写规则的比例 | 100% |

指标异常时的第一反应是查流程（哪个环节在失效），不是改指标。

## 4. 决策日志复盘闭环

分身的进化机制，每次园艺审计执行：

1. 扫描日志中用户 reject / 事后标记错误的决策
2. 逐条归因到三类之一：
   - **宪章缺规则**（用户的标准没被写出来）→ 提议修订宪章，给用户看 diff
   - **域档案缺知识**（领域事实判断错了）→ 补充对应域档案
   - **阈值不对**（指标灵敏度过高/过低）→ 调整决策矩阵参数并记录
3. 回写对应资产，**不改个案结果了事**
4. 同一类错误第二次出现 → 该领域相关操作降级（自治阶梯降一级）

## 5. 专家模式资产清单

用户想深入调教系统时，指向以下资产（小白模式下不主动暴露）：

| 用户意图 | 指向 |
|---|---|
| 改收录/排斥标准 | `00_系统/宪章.md` |
| 看系统判断力历史 | `00_系统/决策日志/` |
| 调某领域判断标准 | `00_系统/domains/<域>.md` |
| 看健康趋势 | `00_系统/atlas/健康基线.md` |
| 调自动化程度 | `00_系统/atlas/自治状态.md` |

引导原则：给文件位置 + 一句人话解释它是干嘛的 + 改之前先问用户想达到什么效果。
